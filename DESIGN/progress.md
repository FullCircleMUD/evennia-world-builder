## 2026-05-06 (later same day)

- **Spike 2 — `contents:` recursion + same-file location cross-references — shipped end-to-end.** Live verified against the test repo: `wb_build zone=millholm room=bakery` cleans + creates 5 objects (the bakery + a brick oven, display case, baker, and honey loaf), and the four nested entities are placed *inside* the bakery — `examine Goldencrust Bakery` lists the four contents, `get loaf` succeeds because the loaf's location is the room the player is in, `examine brick oven` shows the right description. 200 unit tests green (171 → 200, +29 across the four steps).

  The spike landed incrementally as four small steps:

  - **Step 1 — Loader flattens.** `LoadedEntity` grew `is_nested: bool = False`; the Loader's file-leaf branch now flattens a top-level mapping (or list of mappings) plus any `contents:` block into a flat depth-first pre-order list. The `contents` key is popped from the emitted parent body; nested entities inherit the parent's `path` and `location` dict (the file is the atomic deployment unit). 10 new LoaderTest methods.

  - **Step 2 — Loader synthesises `location:` on nested entities.** `LoadedEntity` grew `had_author_location: bool = False`. During flatten, before any modification, the Loader records whether the author wrote a `location:` key, then unconditionally synthesises `content["location"] = {deployment_file: parent.path, deployment_id: parent.deployment_id}` on every nested entity. Depth recursion points at the *immediate* parent at every level (gem in backpack in room places the gem in the backpack, not the room). 9 new LoaderTest methods.

  - **Step 3 — Validator widens shape, refuses author-written `location:` on nested, collapses `TOP_LEVEL_PREDICATES`.** `_check_location_well_formed` accepts `null` OR a strict `{deployment_file: non-empty str, deployment_id: non-negative int}` cross-ref dict (extra keys refused, `bool` excluded from int). New `_check_no_author_location_on_nested` reads the LoadedEntity's `is_nested` + `had_author_location` flags and refuses the violation. The earlier `TOP_LEVEL_PREDICATES` split collapsed into `PER_ENTITY_PREDICATES` since the Loader's synthesis means the location predicate now applies uniformly. 13 new validator tests; one existing test rewritten.

  - **Step 4 — Builder resolves cross-refs in-pass.** `Builder._built_by_id: dict[(deployment_file, deployment_id), obj]` populated as each entity is created. New `_resolve_location` does `null → None` or dict lookup against the map; raises `BuilderError` with a clear "no such entity has been built" message if the lookup misses. Single-pass build relies on the Loader's depth-first pre-order for parent-before-child ordering; same-file forward refs on top-level entities are refused (author reorders). 7 new BuilderTest methods using `unittest.mock` against `evennia.utils.create.create_object` and `evennia.utils.search.search_tag`.

  Pending for spike 4: `exits:` recursion, cross-file location cross-references (DB tag-search fallback for parents already in the DB from a previous invocation), and a forward-ref refusal predicate to surface same-file forward refs at validate time instead of at the Builder. See [DESIGN/builder.md](builder.md), [DESIGN/discovery-and-loading.md](discovery-and-loading.md), [DESIGN/validator.md](validator.md), [DESIGN/deployment-identity.md](deployment-identity.md) for the updated design.

## 2026-05-06

- **Spike 1 complete — single-entity Builder + validator coverage of every standard predictable per-object dimension.** The library now reads-validates-builds a single entity from YAML to a real Evennia object, idempotently. Live verified against `evennia-world-builder-test-yaml` over GitHubReader (and against a local checkout via LocalReader); the showcase bakery comes out with the right typeclass (`typeclasses.rooms.BakeryRoom`), aliases, all lockstring overrides, all attributes (including YAML overriding the typeclass `at_object_creation` default `loaves_available=10` → `24`), all author tags, and the auto-set `wb_deployment_file` / `wb_deployment_id` identity pair. Re-runs sweep prior deployments cleanly via cleanup-on-rebuild — players in deleted rooms are safely relocated to home before deletion. New [DESIGN/builder.md](builder.md) captures the per-entity construction order and the cleanup model. Validator now ships nine Tier 1 predicates, one Tier 2 stateful check, and one Tier 3 Evennia-runtime predicate; mandatory field set is `{deployment_id, name, typeclass, location}`. `definitions.yaml` grows a `strict-attributes` scaffold (refused-on-true today; ready for typeclass-introspection in a future spike). 161 unit tests green. Out-of-spike (next): recursion into `exits:` / `contents:` and cross-reference resolution.
- Validation gating model + `--force-validate` flag landed. `definitions.yaml` carries `repo-ci-pre-validation` (default `false`); when false, `wb_build` pre-validates the whole repo before every build, when true it skips the walk and trusts external CI. Per-invocation `--force-validate` flag overrides the setting (paranoid one-off). Library never inspects or verifies the consumer's CI setup — defaults to safe, makes the cost of "fast but unsafe" obvious via long warning comments in the template. Three-tier cross-reference correctness (CI gate primary, Builder DB-lookup at create-time secondary, inline scope-bounded validator always) covers the failure modes without forcing whole-repo walks on every single-file redeploy. wb_build arg parser extended to handle `--flag` tokens alongside `level=value`. 84 unit tests green. See [DESIGN/validation-gating.md](validation-gating.md).

## 2026-05-05

- Validator architecture + first checks shipped, plus standalone `wb-validate` CLI. Two-tier check model: stateless predicates (`PER_ENTITY_PREDICATES`, pure `(entity) -> finding | None`) and stateful checks (methods that read/update the per-file `{deployment_file: {ids}}` index incrementally during the per-entity pass). Complete-refusal semantics: every finding is gathered before `validate()` raises `ValidatorError`, and both invocation paths (in-game `wb_build`, standalone `wb-validate`) surface the full message list before halting. First two checks landed: `deployment_id` is mandatory non-negative integer (rejects `bool`); within a file, `deployment_id` is unique. New `LocalReader` slots into the existing reader dispatch (`WORLDBUILDER_READER`); the new console-script `wb-validate` runs the same Reader → Definitions → Finder → Loader → Validator pipeline outside Evennia for dev iteration / CI / pre-commit. 71 unit tests green; live smoke against test repo (clean run) and a temp synthetic repo (refusal path with stderr halt-summary, exit 1) both verified. See [DESIGN/validator.md](validator.md), [DESIGN/cli.md](cli.md).
- Deployment identity contract anchored: every entity is identified by `(deployment_file, deployment_id)`. `deployment_file` is the full Reader path (set automatically by Builder); `deployment_id` is an author-supplied integer in YAML, mandatory and unique within its file. File is the atomic deployment unit — redeploy = clean-by-file-tag + recreate. Cross-references default `deployment_file` to the current file when omitted; explicit when crossing files. Anchors all downstream work (Validator, Builder cleanup, partial deploys). See [DESIGN/deployment-identity.md](deployment-identity.md). Test SCAFFOLD fixture and live test repo (`evennia-world-builder-test-yaml`) updated to carry `deployment_id` on every entity.
- Library v0 — `wb_build` command shipped end-to-end. Auto-installs into AccountCmdSet via AppConfig (works OOC + IC, superuser-only). Parses operator args (`wb_build all` or `wb_build level=value ...`), loads definitions, validates query against declared levels, walks the manifest via Finder, recursively reads matching content via Loader, and dumps entities for visual verification. Bare `wb_build` is a no-op; the explicit `all` keyword is required for a full-world build (guard rail). Validator + Builder phases not yet implemented. 50 unit tests green; live verified against the private test repo. See [DESIGN/library-commands.md](library-commands.md).
- Library v0 — discovery + loading: `Definitions`, `Finder`, `Loader` shipped under `src/evennia_world_builder/`. Reads `definitions.yaml` once per command, walks the manifest tree (per-folder `index.yaml`) to find the entry point matching an operator query, then recursively reads all leaf content under it. Reader API evolved — `read(path)` takes the path per-read so one configured Reader serves many files. Index order = execution order (consumers control creation-order dependencies via index order). 36 unit tests green. Settles spike 1's deferred "indexing convention" question. See [DESIGN/discovery-and-loading.md](discovery-and-loading.md).
